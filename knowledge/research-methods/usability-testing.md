# Usability Testing

**Status:** ADOPT  
**Last updated:** 2026-08-22  
**Sources:** Maze, Optimal Workshop, Usability.gov, Nielsen Norman Group (filtered)

---

## Purpose

Evaluate whether people can use a design to complete key tasks effectively, efficiently, and with satisfaction.

---

## When to use

- Before committing to a design direction
- After a significant redesign
- When analytics show drop-offs but you don’t know why
- Before launch of a critical flow

---

## Moderated vs Unmoderated

| Type | Best for | Trade-offs |
|------|----------|------------|
| **Unmoderated** (Maze, etc.) | Speed, volume, remote | Less depth, no follow-up questions |
| **Moderated** | Deep understanding, complex tasks | Slower, more expensive, scheduling |

Default recommendation under time pressure: start with unmoderated, escalate to moderated only if needed.

---

## Minimum viable usability test

1. Define 3–5 critical tasks (tied to real user goals)
2. Write clear success criteria for each task
3. Recruit 5–8 participants from the right segment
4. Run the test
5. Analyze: success rate, time on task, errors, qualitative notes
6. Prioritize findings by impact on the decision

---

## Key metrics to capture

- Task success rate (direct vs indirect)
- Time on task
- Error / misclick rate
- Confidence / satisfaction (simple post-task question)
- Qualitative comments and observed friction

Always report sample size and date range.

---

## Common anti-patterns

- Testing with the wrong users
- Tasks that are too leading or artificial
- Ignoring qualitative comments and only looking at success rates
- Running a test without a clear decision it needs to influence
- Not sharing findings in a way the team can act on
