# 1-Week Validation Pack

**Status:** Done · **Priority:** Medium  
**Use when:** Stakeholder asks for “a bit more than a spike” but not a full research quarter. Builds on 1-day and 2–3 day packs.

---

## When to use

- Ambiguous problem + real users available  
- Need both **behavioral** and **attitudinal** signal  
- Design decision must stick past one meeting  

If you only have 1–2 days → use shorter packs. Don’t pad a week with process theater.

---

## Day-by-day (default)

| Day | Focus |
|-----|--------|
| **1** | Align question, success criteria, constraints; desk research; instrument or analytics pull if live product |
| **2** | Stakeholder / expert interviews (3–5); map assumptions |
| **3** | User sessions (5–8) moderated **or** unmoderated tasks + diary lite |
| **4** | Synthesize: themes, evidence table, kill/keep hypotheses |
| **5** | Prototype or copy/flow experiment for top risk |
| **6** | Test prototype (5 users or guerrilla + analytics if shipped flag) |
| **7** | Decision doc: recommendation, risks, open questions, next experiment |

Compress weekends only if stakeholders pre-agree; quality > calendar fill.

---

## Outputs (minimum)

1. One-page problem / question  
2. Evidence log (quote / metric / session note → claim)  
3. Decision record (this vs that + why)  
4. Next measurement (event or research)  

---

## Guardrails

- No fake precision metrics  
- Confidential work: sanitize in portfolio later (see confidential-and-nda-cases)  
- Prefer methods from Optimal/Maze/Nielsen-class practice; don’t invent methodology
